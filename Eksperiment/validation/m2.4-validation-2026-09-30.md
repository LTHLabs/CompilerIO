## G2 — Execution abstraction: BLOCKED (Linux half PASS)
MEASURED / CODE on Linux:
- Equivalence: with `subprocess` intercepted, the `ccbcc91` `EnvironmentManager` and the new one issue **identical** argv, cwd,
  flags and environment for compile, `merge_bin` and dependency preparation (3/3 calls), re-checked on the final code.
- `environment.py` contains no `unshare`, `mount`, `killpg`, `SIGKILL`, `subprocess`, `_winapi` or `taskkill`.
- `WindowsBackend` source contains no `unshare`, `mount`, `killpg`, `getpgid`, `SIGKILL`, `"sh"`, `start_new_session`, `/bin/`, `bind`.
- `select_backend`: linux → `LinuxBackend`; `win32` → `WindowsBackend`; `darwin` → `UnsupportedHostBackend` (patched `sys.platform`).
- `WindowsBackend.check_host` refuses a non-Windows host, a non-x64 machine, and the Linux Base
  (`system=['linux_x86_64']`) even when the host is patched to look like Windows x64.
- Offline-violation detector: flags `Library Manager: Installing …`, `Tool Manager: Installing …`, `Downloading [###]`; no false
  positive on a real Linux compile-phase log; ignores the word mid-line in compiler errors.

Not validated: any `WindowsBackend` execution (junction creation, direct PlatformIO run, UTF-8 decoding, `taskkill` tree kill).

## G1, G3 — BLOCKED
No native Windows host was reachable (`/mnt/c`, `pwsh`, `powershell.exe`, `cmd.exe` absent). The provisioning script was not
executed. No Windows claim is made.

Prepared (CODE / registry, not an install):
- PlatformIO Registry API: all pinned versions exist for `windows_amd64` (toolchain owner is `espressif`, all others `platformio`).
- PlatformIO `PackageSpec` parses every pinned spec with the exact version requirement.
- Script pins equal the Linux Base versions/owners exactly and cover `EnvironmentManager.MARKERS`.

## G5 — Cross-host integrity: BLOCKED
Linux half MEASURED: Linux Base unchanged; merge offsets correct. Windows half requires a provisioned Windows Base and Windows
artifacts. Design guarantee (CODE): the Windows backend refuses a Base whose toolchain is not `windows_amd64`, and the provisioning
script refuses non-native packages and version drift.

## Windows limitations (by design, M2.4)
- No kernel isolation: Base writes and network use during compile are **detected, not prevented**.
- Detection relies on the manifest (before/after) and PlatformIO log markers; network calls that print neither are not detected.
- Timeout uses `taskkill /T /F` on the live tree; processes already re-parented away from the tree are not covered.
- Hub mode on Windows is not in scope.

## Verdict
**M2.4 is NOT complete.** Linux refactor and regression PASS; all Windows-host gates (G1, G3, and the Windows halves of G2/G5)
are BLOCKED pending a native Windows host.
