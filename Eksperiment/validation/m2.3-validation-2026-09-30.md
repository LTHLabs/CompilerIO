# M2.3 Execution Mode Foundation — Validation Report

**Date:** 2026-09-30
**Branch:** `milestone-2-library-handling`, HEAD `f45ad65` (M2.3 changes uncommitted at time of writing)
**Evidence policy:** **MEASURED** = observed in a real run of the agent / real browser. **CODE** = read in source or checked
in-process. **INFERENCE** = reasoning not directly observed. No performance or timing figures are reported except the pairing-code
expiry timing, which is the behaviour under test.

---

## 1. Objective and scope

Add a Dual-Mode execution foundation to the Local Agent:
- **Personal** (default): bind `127.0.0.1`, one local user.
- **Hub** (explicit opt-in): bind `0.0.0.0`, several browser clients on a trusted LAN.

In scope: mode selection and bind enforcement, prepare/build serialization, a bounded waiting-build limit, multi-client pairing with
per-session identities, build ownership, Hub host-only prepare, Web App connectivity to a Hub agent.

Out of scope (not implemented): mDNS/discovery, tunnelling, TLS, mobile execution, UI redesign, parallel workers, per-client
retention, persistent accounts/roles, dependency cache, performance work.

## 4. Results by gate

### G1 — Personal default and bind enforcement: PASS (MEASURED)
- Launcher with no mode: `ss -ltn` showed only `127.0.0.1:8765`; loopback request → 200; request to LAN IP `192.168.1.74:8765` →
  connection refused.
- Legacy `uvicorn … --host 127.0.0.1` command still starts in Personal mode.
- Personal mode deliberately bound to `0.0.0.0` by hand: loopback → 200; LAN `GET /environment/status`, `POST /session/pair` and
  CORS preflight → 403 `Personal mode accepts loopback clients only.`
- CODE: 9 configuration cases and 8 loopback-host cases checked in-process.

### G2 — Hub explicit opt-in and startup guard: PASS (MEASURED)

- Hub with `http://192.168.1.74:3000`: listening on `0.0.0.0:8765`, LAN warning banner printed, LAN request → 200; pairing from a
  non-allowlisted origin → 403; CORS preflight allowed only for the configured origin.

### G5 — Bounded global waiting queue: PASS (MEASURED)

  no project directory created by rejected submissions; a further single submission → 429.

- An earlier run with limit 1 also admitted exactly 1 of 10; that run's final assertions were not recorded because of a test-script

- CODE: default 3; values 0 / −2 clamp to 1; non-integer falls back to 3.

### G6 — Prepare serialized with builds: PASS (MEASURED)

### G3 — Multi-client pairing and session identities: PASS (MEASURED + CODE)

## 7. Known limitations and risks

MEASURED:
- Each `POST /build` runs the existing synchronous Base-manifest check inside the event loop and blocks the agent for several seconds;
  under a burst, requests (including status polls) wait. Rejected submissions also pay this cost (limit is checked after readiness).
- A build submitted while the environment is `PREPARING` gets 409 (pre-existing readiness check), not a queue slot.

CODE / INFERENCE:
- Hub is for a trusted LAN only: plain HTTP; tokens can be sniffed; tokens do not expire until restart; no pairing rate limit
  (codes ≈ 48 bits, one valid at a time, replaced after use/expiry).
- Host-only prepare trusts the TCP source: any local process on the host with a paired token counts as host. The host operator must
  use `http://localhost:3000` (that origin must be in the Hub allowlist).
- Manual `uvicorn` starts are not protected against trusted forwarded headers (`--forwarded-allow-ips '*'` would let a remote client
  appear as loopback); only the launcher sets `proxy_headers=False`.
- Queue limit and retention are global: one session can fill the queue; one session's builds can evict another's (owner then gets 404).
- `QUEUED` counting is literal: at limit 1 a second submission in the instant before the first build starts can be rejected.
- Pairing-code expiry is checked once per second, so a code can be accepted for up to about 1 s past its nominal expiry.
- Web App: CSP `http://*:8765` allows any host on port 8765 (http only); the agent port 8765 is assumed by `api.js` and CSP
  (`COMPILERIO_PORT` changes need both edited); `#agentUrl` is `readonly` (pre-existing), so manual override is not user-typable;
  `pairing.js`/`state.js` keep unused `127.0.0.1` defaults.
- Pre-existing UX issues unchanged: page reload needed after pair and after prepare.
- `/environment/status`, `/boards`, `/frameworks` are unauthenticated; status exposes the Base Environment path.

## 8. Verdict

**M2.3 Execution Mode Foundation — PASS** for the stated scope: all gates G1, G2, G3, G4, G5, G6, G7, the live 300 s pairing
expiry, and the Personal regression passed with the Base Environment fingerprint unchanged and no orphan processes. Hub mode is a
trusted-LAN foundation with the limitations listed in section 7; it is not claimed to be secure for untrusted networks.
